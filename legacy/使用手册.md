# ECC 局部启用工具 · 使用手册

> 目标：ECC 全局默认**禁用**，只在**需要的项目里**启用；同时支持 **Claude Code** 与 **Codex**，
> 二者互不影响、互不冲突。本工具只往项目目录写文件，**绝不改动全局**（`~/.claude`、`~/.codex`）。

## 1. 名词与路径约定

| 名称 | 路径 | 说明 |
|---|---|---|
| 中央库（源） | `E:\Work2\AI_Work\tool\ECC\ECC` | 克隆下来的 ECC 仓库，只是"源"，本身不激活任何东西 |
| 工具目录 | `E:\Work2\AI_Work\tool\ECC\ECC局部启用工具` | 存放 `ecc-on.ps1` / `ecc-off.ps1` / 本手册 |

- Claude 用 `install.ps1 --target claude-project`（写 `.\.claude\`），**永远不要用** `--target claude`（那是写全局 `~/.claude`）。

## 3. 全局保持禁用（原理 + 自查）

**原理**：本工具从不往全局目录写东西；不启用 ECC 的 Claude 插件；不动 `~/.codex/config.toml`。
因此"全局"天然是关的——没有启用过的项目，打开 Claude / Codex 跟没装 ECC 一样。

**自查清单**（确认全局确实干净）：

```powershell
# Claude：settings.json 里不应有 "ecc@ecc": true
Get-Content "$env:USERPROFILE\.claude\settings.json" | Select-String "ecc"

# Claude：全局不应有 ECC 的 agents/hooks/rules 目录（你已有的 skills/plugins 是别的插件，无关）
Get-ChildItem "$env:USERPROFILE\.claude" -Directory | Select-Object Name

# Codex：全局 config.toml 不应含 ecc
Get-Content "$env:USERPROFILE\.codex\config.toml" | Select-String "ecc|ECC"
```

如果以前不小心做过全局安装，用 ECC 仓库自带的卸载器清理（这是清理**全局**的）：
```powershell
node E:\Work2\AI_Work\tool\ECC\ECC\scripts\uninstall.js --dry-run   # 先看
node E:\Work2\AI_Work\tool\ECC\ECC\scripts\uninstall.js             # 再删
```

## 4. 脚本位置与参数表

脚本在：`E:\Work2\AI_Work\tool\ECC\ECC局部启用工具\`

调用方式（任选其一）：
```powershell
# 1) 进到项目目录，用全路径调用（推荐）
cd D:\path\to\your\project
E:\Work2\AI_Work\tool\ECC\ECC局部启用工具\ecc-on.ps1

# 2) 用 -Path 指定项目，不必先 cd
E:\Work2\AI_Work\tool\ECC\ECC局部启用工具\ecc-on.ps1 -Path D:\path\to\your\project
```

### ecc-on.ps1 —— 在项目里启用

| 参数 | 默认 | 说明 |
|---|---|---|
| `-Harness` | `both` | 启用谁：`both` / `claude` / `codex` |
| `-Profile` | `core` | **仅 Claude** 的安装规模：`minimal` / `core` / `full` |
| `-Rules` | `common` | 复制到 `.claude\rules\ecc\` 的规则目录，逗号分隔（如 `common,zh,typescript`）|
| `-CodexFull` | 关 | Codex 用**档位②**（整个 `.codex\`）。不加=档位①（仅指令）|
| `-CodexOverride` | 关 | Codex 指令用 `AGENTS.override.md`（在本项目内屏蔽全局 `~/.codex/AGENTS.md`）|
| `-Mcp` | — | 档位②显式指定保留哪些 MCP（逗号分隔），给了就完全按它来 |
| `-KeepMcp` | 关 | 档位②保留**全部** MCP，不裁剪 |
| `-KeepPlaywright` | 关 | 自动裁剪时额外保留 playwright |
| `-Path` | 当前目录 | 目标项目根 |
| `-EccRepo` | `..\ECC` | 中央库位置（默认取工具目录上一级的 `ECC`）|
| `-DryRun` | 关 | 只打印计划与 MCP 裁剪决策，不写文件 |

### ecc-off.ps1 —— 在项目里停用

| 参数 | 默认 | 说明 |
|---|---|---|
| `-Harness` | `both` | 停用谁：`both` / `claude` / `codex` |
| `-Path` | 当前目录 | 目标项目根 |
| `-DryRun` | 关 | 只打印将删除什么，不实际删 |
| `-Force` | 关 | 清单缺失时仍按标准路径强删（谨慎，可能删到你自己的 `.claude\`/`.codex\`）|

> `ecc-off` 默认**只删本工具创建的东西**（依据项目根的 `.ecc-local.json` 清单）；
> 启用前就已存在的同名 `.claude\` / `.codex\` / `AGENTS.md` 不会被误删。

## 5. 在项目里启用（命令示例）

```powershell
cd D:\path\to\your\project

# 最常用：Claude + Codex 一起（Codex 走轻量档位①，不动你平时的运行策略）
ecc-on.ps1

# 只启用 Claude，规模 full，并带中文规则
ecc-on.ps1 -Harness claude -Profile full -Rules common,zh

# 只启用 Codex，走完整档位②（含 config.toml/agents/MCP），自动裁剪 MCP
ecc-on.ps1 -Harness codex -CodexFull

# Codex 档位② 且保留 playwright、外加显式只留 memory+context7
ecc-on.ps1 -Harness codex -CodexFull -Mcp memory,context7

# 先看计划、不动文件
ecc-on.ps1 -CodexFull -DryRun
```

**默认行为**：`-Harness both` + Claude `core` + Codex 档位①。

## 6. 启用后怎么用

### Claude Code
- 在**该项目**打开 Claude Code。
- 输入 `/` 可见 ECC 的命令/技能；subagents 自动可用；hooks 在编辑/执行等事件触发。
- 首次可能提示是否信任项目的 hooks/settings → **同意**。
- `/memory` 可查看本项目加载了哪些 rules。
- 换到没启用的项目 → 完全看不到 ECC。

### Codex
- 在该项目目录运行 `codex`。
- **首次务必"信任该项目"**，否则项目级 `.codex\config.toml`（档位②）不会被加载。
- 档位①：ECC 指令（来自根级 `AGENTS.md`）生效，运行策略/MCP 跟你平时一致。
- 档位②：额外启用 ECC 的：
  - 运行预设 profile：`codex -p strict`（只读）/ `codex -p yolo`（免确认）
  - 子 agents：explorer / reviewer / docs_researcher
  - 裁剪后的 MCP（默认 `context7` / `memory` / `sequential-thinking`）
- 换到没启用的项目 → Codex 回到你全局默认行为。

## 7. 停用 / 卸载

```powershell
cd D:\path\to\your\project

ecc-off.ps1                 # 两个都停（删除本工具创建的 .claude\ / .codex\ / AGENTS*.md）
ecc-off.ps1 -Harness codex  # 只停 Codex，保留 Claude
ecc-off.ps1 -DryRun         # 先看会删什么
```

停用只动项目内的文件，**全局 `~/.claude`、`~/.codex` 完全不受影响**。

## 8. MCP 自动裁剪说明

**只发生在 Codex 档位②**，改的是**项目里的副本** `.\.codex\config.toml`，**不影响全局**那份。
（Codex 读配置是只读的，项目 config 永远不会回写全局文件。）

**为什么裁**：ECC 默认开了 6 个 MCP（github / context7 / exa / memory / playwright / sequential-thinking），
启动时 Codex 会逐个拉起。没 key / 没装环境的会启动失败或卡顿，还会白占上下文与进程。裁掉=更快更干净。

**自动裁剪规则**（不加 `-Mcp` / `-KeepMcp` 时）：

| MCP | 默认 | 条件 |
|---|---|---|
| `sequential-thinking` | ✅ 保留 | 无需 key |
| `memory` | ✅ 保留 | 无需 key |
| `context7` | ✅ 保留 | 可无 key 运行 |
| `github` | 视情况 | 检测到 `GITHUB_PERSONAL_ACCESS_TOKEN`/`GITHUB_TOKEN`/`GH_TOKEN` 才保留 |
| `exa` | 视情况 | 检测到 `EXA_API_KEY` 才保留 |
| `playwright` | ❌ 移除 | 走浏览器扩展、较重；需要时加 `-KeepPlaywright` |

**覆盖方式**：
- `-Mcp github,memory` → 只留这两个，其余全裁（不看环境变量）。
- `-KeepMcp` → 一个都不裁，全保留。

此外，Windows 下脚本会自动**注释掉** ECC config 里依赖 macOS `terminal-notifier` 的 `notify` 设置，避免报错。

## 9. 互不冲突原理 & 已知限制

**为什么 Claude 和 Codex 不打架**：它们读完全不同名的文件/目录——

| | Claude Code | Codex |
|---|---|---|
| 指令文件 | `CLAUDE.md`（不读 AGENTS.md） | `AGENTS.md`（不读 CLAUDE.md） |
| 配置目录 | `.claude\` / `~/.claude\` | `.codex\` / `~/.codex\` |
| MCP 来源 | `.mcp.json` / `.claude\settings.json` | `.codex\config.toml` |

放在同一个项目里也互不读取对方的目录，天然隔离。

**已知限制（诚实说明）**：
1. **Codex 档位②会在该项目内覆盖你全局的运行策略**（`approval_policy`/`sandbox_mode`/`web_search`/MCP）。
   不想被覆盖就用档位①。
2. **Codex 项目级 config 仅对"受信任项目"生效**，第一次要手动信任。
3. **同一项目同时开 Claude + Codex**：两边各起各的 MCP 进程（如各一个 server），不冲突，但**重复占资源 + 双倍 API 调用**。同时用时建议在一边关掉重叠的 MCP。
4. ECC 官方**不支持 Cline**，本工具也不含 Cline；如需另说。

## 10. Git 卫生

启用后项目里会多出 `.claude\` / `.codex\` / `AGENTS*.md` / `.ecc-local.json`。
若不想提交（或避免泄露 MCP 密钥），加到 `.gitignore`：

```gitignore
.ecc-local.json
.claude/
.codex/
AGENTS.md
AGENTS.override.md
```

> 想让团队共享这套配置则相反——但**务必先确认 config 里没有写死任何 API key**（密钥应走环境变量）。

## 11. 常见问题排错（FAQ）

**Q：运行脚本报"无法加载，因为在此系统上禁止运行脚本"。**
A：放宽当前用户的执行策略，或单次绕过：
```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned      # 一次性设置
# 或单次：
pwsh -ExecutionPolicy Bypass -File "E:\Work2\AI_Work\tool\ECC\ECC局部启用工具\ecc-on.ps1"
```

**Q：Claude 装好了但没有 rules？**
A：rules 不随插件/安装器自动分发，本工具已自动复制 `common` 到 `.claude\rules\ecc\`；要更多语言用 `-Rules common,python,...`。

**Q：Codex 启动后 ECC 的 MCP/profile 没生效？**
A：99% 是没"信任该项目"。在该项目重新运行 `codex` 并信任；确认用的是档位②（`-CodexFull`）。

**Q：某个 MCP 启动失败/刷错误？**
A：多半是缺 key 或缺环境。重跑启用并用 `-Mcp` 只保留你要的，或 `ecc-off.ps1 -Harness codex` 后再以更小集合启用。

**Q：误删风险？**
A：`ecc-off` 默认只删清单记录里"由本工具创建"的路径；启用前就存在的同名目录不会动。不确定先 `-DryRun`。

**Q：中央库能移动吗？**
A：能，但移动后用 `-EccRepo` 指定新位置，或同步移动整个 `tool\ECC` 目录（脚本默认取"工具目录的上一级 \ECC"）。

## 12. 附：清单文件 .ecc-local.json

启用时写在**项目根**，记录本工具到底装了什么，供 `ecc-off` 精确卸载。示例：

```json
{
  "tool": "ecc-local",
  "version": 1,
  "enabledAt": "2026-06-04T10:31:34",
  "eccRepo": "E:\\Work2\\AI_Work\\tool\\ECC\\ECC",
  "harness": "both",
  "claude": { "enabled": true, "profile": "core", "rules": ["common"], "createdByUs": true },
  "codex":  { "enabled": true, "mode": "full", "override": false,
              "agentsFile": null, "agentsCreatedByUs": false, "codexCreatedByUs": true,
              "mcpKept": ["sequential-thinking","memory","context7"],
              "mcpRemoved": ["github","exa","playwright"] }
}
```

| 字段 | 含义 |
|---|---|
| `createdByUs` / `codexCreatedByUs` / `agentsCreatedByUs` | 该路径是否由本工具创建（卸载时只删 true 的）|
| `mode` | Codex 档位：`light`(①) / `full`(②) |
| `mcpKept` / `mcpRemoved` | 档位②实际保留/裁掉的 MCP |
